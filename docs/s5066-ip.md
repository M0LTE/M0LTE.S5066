# s5066-ip: IP over STANAG 5066

`s5066-ip` carries IPv4 and IPv6 over a STANAG 5066 link. It is the IP client of Annex U: it binds SAP 9 on a 5066 node (s5066d, pdn-soundmodem, or another vendor's node that serves the SIS) and gives Linux a network device, `s5066`. Anything you route into that device goes over HF to the station whose network it is for.

It suits light traffic: ping, small UDP exchanges, the odd message. The annex itself warns that TCP and web browsing over HF work badly under load [Ed4 U.3, p.U-2].

## How it works

- Each IP datagram travels as one 5066 message, unchanged and never split. The device's MTU is set to the node's (2048 bytes for s5066d), so Linux sizes packets to fit.
- You say which 5066 node each IP network lives behind (`routes`). The longest matching prefix wins, and `default_node` catches the rest. Packets for a network with no route are dropped.
- By default everything goes ARQ (retransmitted until confirmed) at priority 4, and ping and other ICMP at priority 8 so it gets through first. `rules` change that per protocol, port or destination, for example DNS as non-ARQ.
- Multicast is dropped unless you give a 5066 group address in `multicast`; then it goes non-ARQ to that group.
- `allow`, if you set it, is an allow-list: anything it does not match is dropped. Without it everything is allowed.
- When the node says it is busy (flow control) or is not reachable, up to `queue_limit` packets (default 32) wait; when that is full, new packets are dropped. If the node restarts, `s5066-ip` reconnects every 5 s and the device stays up.
- A packet too big for the link with "don't fragment" set, and any IPv6 packet too big, gets an ICMP "too big" answer carrying the MTU, so path MTU discovery works. An IPv4 packet that may be fragmented is dropped instead; the kernel fragments to the device MTU before it gets that far.
- Every ten minutes, when anything changed, it logs one line of counters (sent, confirmed, rejected, delivered, and drops by reason).

It is a router: the device has no addresses or routes until you add them. Only tun (layer 3) is supported, not bridging.

## Install

From the packet-net apt repository:

```
sudo apt install s5066-ip
sudo cp /etc/s5066-ip/example.json /etc/s5066-ip/s5066-ip.json
sudo nano /etc/s5066-ip/s5066-ip.json
```

The service is installed but not enabled. It runs as a throwaway user with only the `CAP_NET_ADMIN` capability, which it needs to create the device. Run by hand it needs the same: `sudo s5066-ip s5066-ip.json`.

## Two stations

Station A is 5066 node `0.0.1.1` with network `10.66.1.0/24` and `fd66:1::/64`; station B is node `0.0.1.2` with `10.66.2.0/24` and `fd66:2::/64`. Each runs s5066d on its radio and s5066-ip beside it.

Station A, `/etc/s5066-ip/s5066-ip.json`:

```json
{
  "sis": "127.0.0.1:5066",
  "device": "s5066",
  "routes": [
    { "prefix": "10.66.2.0/24", "node": "0.0.1.2" },
    { "prefix": "fd66:2::/64", "node": "0.0.1.2" }
  ]
}
```

Station A, addresses and routes in a drop-in, `sudo systemctl edit s5066-ip`:

```ini
[Service]
ExecStartPost=+/usr/sbin/ip addr add 10.66.1.1/32 dev s5066
ExecStartPost=+/usr/sbin/ip addr add fd66:1::1/128 dev s5066 nodad
ExecStartPost=+/usr/sbin/ip route add 10.66.2.0/24 dev s5066
ExecStartPost=+/usr/sbin/ip route add fd66:2::/64 dev s5066
```

The `+` runs those lines with full privileges; the unit waits until the device is up before running them. Station B is the mirror image (routes to `0.0.1.1`, its own addresses `10.66.2.1` and `fd66:2::1`, routes to `10.66.1.0/24` and `fd66:1::/64`). Then on each:

```
sudo systemctl enable --now s5066-ip
ping -I 10.66.1.1 10.66.2.1
```

A ping takes a while: the two nodes have to set up an HF link first, then each packet waits for the channel. Use `ping -W 120`.

If the stations route for a LAN behind them, turn on forwarding (`net.ipv4.ip_forward=1`, `net.ipv6.conf.all.forwarding=1`) and route the far LAN into `s5066` the same way.

## Configuration

| Key | Meaning | Default |
|---|---|---|
| `sis` | The node's SIS, `host:port` | `127.0.0.1:5066` |
| `device` | Name of the tun device | `s5066` |
| `routes` | List of `{ "prefix", "node" }`: which 5066 node each IP prefix is behind | none |
| `default_node` | 5066 node for anything no route matches | none (dropped) |
| `multicast` | `{ "group": "16.0.0.9", "repeats": 1 }`: send IP multicast non-ARQ to this group | none (dropped) |
| `mode` | `arq` or `non_arq` for packets no rule names | `arq` |
| `priority` | 5066 priority 0 (lowest) to 15 | 4 |
| `icmp_priority` | priority of ICMP and ICMPv6 | 8 |
| `rules` | List, first match wins: `prefix`, `protocol` (`icmp`, `icmpv6`, `tcp`, `udp` or a number) and `port` (source or destination) to match; `mode` and/or `priority` to set | none |
| `allow` | List of matches as in `rules`; anything else is dropped | everything allowed |
| `queue_limit` | packets held while the node is busy | 32 |

5066 addresses are written `w.x.y.z`; a `w` of 16 to 31 is a group, so `31.255.255.255` is broadcast. The file may carry `//` comments.

## Testing without a radio

`tools/s5066-ip/netns-test.sh` builds two network namespaces on one machine, each with an s5066d (the bench configuration over UDP audio) and an s5066-ip, adds the addresses and routes above, and pings across in IPv4 and IPv6. It needs root and deletes everything it made when it ends; run it on a throwaway machine. CI runs it on every pull request that touches s5066-ip.

The standard's requirements and our choices where it is silent are rows U-0001 to U-0044 of `matrix/U.tsv` in [s5066-conformance](https://github.com/M0LTE/s5066-conformance).
